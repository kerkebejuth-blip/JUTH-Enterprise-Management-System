# Definition of Done

## Status

Version 1.0 Enterprise Governance Baseline.

## Purpose

This document defines when work is complete in JUTH HOS.

## Standard Definition of Done

Work is done only when:

- Requirements are implemented within approved scope.
- Architecture is respected.
- Domain Blueprint requirements are satisfied where applicable.
- Tests or validation evidence exist.
- Documentation is updated.
- Security implications are reviewed.
- Clinical safety implications are reviewed where applicable.
- Root quality gates pass.
- Code review is complete.
- ADRs are created where architecture changes.
- Release or ledger records are updated where applicable.

## Documentation Sprint Definition of Done

Documentation work is done when:

- Internal links resolve.
- Placeholder language is removed from finalized baseline documents.
- Authority and status are clear.
- Repository references are consistent.
- No runtime code is unintentionally modified.
