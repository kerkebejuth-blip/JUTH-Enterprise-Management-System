## 1. PURPOSE

This volume defines team responsibilities, collaboration rules, review expectations, and governance controls for JUTH HOS contributors.

## 2. GOVERNANCE ROLES

The project recognizes the following governance roles:

- Project Owner
- Chief Software Architect
- Product leadership
- Clinical reviewers
- Security reviewers
- DevOps reviewers
- Backend engineers
- Frontend engineers
- QA engineers
- AI-assisted contributors

## 3. DECISION AUTHORITY

Architecture decisions follow the hierarchy defined in Volume 00.

Developer preference never overrides the Constitution, approved ADRs, clinical safety, or security requirements.

## 4. COLLABORATION RULES

Contributors shall:

- Work in small reviewable changes
- Communicate risks early
- Respect module boundaries
- Document significant decisions
- Run required validation gates
- Preserve patient safety and confidentiality

## 5. REVIEW EXPECTATIONS

Reviews shall verify:

- Architecture compliance
- Security
- Type safety
- Testing
- Documentation
- Operational impact
- Clinical impact where applicable

## 6. ONBOARDING

New contributors shall review:

- Constitution
- ADRs
- Engineering Handbook
- Repository README files
- Domain blueprint template
- Security policy
- Contribution guide

## 7. ESCALATION

Unresolved architecture, security, clinical safety, or operational concerns shall be escalated to the Chief Software Architect and Project Owner as appropriate.

## 8. SUMMARY

Team governance ensures that JUTH HOS evolves through disciplined collaboration, clear ownership, and accountable review.
