# Architecture Change Process

## Status

Version 1.0 Enterprise Governance Baseline.

## Purpose

This document defines how architecture changes are proposed, reviewed, approved, and recorded.

## Change Triggers

Architecture change process is required for changes affecting:

- Frameworks.
- Repository structure.
- Module boundaries.
- Domain boundaries.
- API standards.
- Database strategy.
- Security model.
- Integration patterns.
- Deployment topology.
- AI behavior.

## Process

1. Identify the proposed change.
2. Compare against the Constitution.
3. Review existing ADRs.
4. Document alternatives.
5. Assess security, clinical, operational, and delivery impact.
6. Create or update ADR.
7. Obtain Chief Software Architect approval.
8. Implement only after approval.
9. Update related documentation.

## Freeze Rule

The governance baseline is frozen. Future architecture changes require ADR approval.
