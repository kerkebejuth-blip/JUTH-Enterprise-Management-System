# ADR-008: Event-Driven Integration

## Status

Approved

## Context

Hospital workflows produce important state changes across modules, including orders, results, dispensing, billing, admissions, and notifications.

## Decision

The platform shall be event-driven ready. Modules should publish domain events for important business state changes, while messaging infrastructure may be introduced later.

## Alternatives

- Direct synchronous coupling for all module communication.
- Immediate enterprise message bus adoption.
- Database polling between modules.

## Consequences

- Domain events must be modeled explicitly.
- Event contracts require versioning and correlation identifiers.
- Messaging infrastructure can be introduced without redesigning domain modules.
- Not every use case requires asynchronous processing immediately.
