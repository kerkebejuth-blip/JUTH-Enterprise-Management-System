# ADR-006: Domain-Driven Design

## Status

Approved

## Context

The hospital platform spans multiple clinical, administrative, financial, and operational domains. These domains require clear language, boundaries, and ownership.

## Decision

JUTH HOS shall use Domain-Driven Design for bounded contexts, aggregates, entities, value objects, domain events, repositories, domain services, and application services.

## Alternatives

- CRUD-first module design.
- Database-table-first design.
- UI-screen-first design.

## Consequences

- Each business module requires a domain blueprint before implementation.
- Business rules belong in domain and application layers.
- Ubiquitous language must be documented.
- Domain boundaries must be protected from integration and persistence concerns.
